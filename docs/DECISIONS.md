# Решения проекта ReadingJournal

**Обновлено:** 27.11.2026. Здесь фиксируются только решения Forvid и явно выделяются вопросы, которые ещё не решены. Запись об архитектуре — **не разрешение на реализацию платных функций**.

## Утверждено

| ID | Решение | Почему |
| --- | --- | --- |
| RJ-DEC-001 | ReadingJournal существует отдельно от Stroysite: свои папка, репозиторий и сессия Codex | Не смешивать данные, задачи и историю |
| RJ-DEC-002 | Роли: Forvid — продуктовые решения/приёмка; ChatGPT — обсуждения, задания, тест-кейсы и документация; Codex — реализация/проверки кода | Чёткая зона ответственности и экономия времени |

| RJ-DEC-004 | Рекомендации персональные, учитывают оценки и темы, автоматически обновляют топ и объясняют совпадения | Отличительная ценность приложения |
| RJ-DEC-005 | **Гибридная архитектура:** AI предлагает темы одной заметки, обычный алгоритм ранжирует кандидатов | Смысловой анализ при проверяемых рекомендациях и контроле стоимости |
| RJ-DEC-006 | Для первого этапа локальная библиотека без регистрации и синхронизации; проект готовится как GitHub-портфолио с публичным демо после отдельного согласования | Быстрый MVP и демонстрация навыков |
| RJ-DEC-007 | Не трогать исходный код на этапе пересмотра документации; реализация идёт через Codex | Разделить планирование и разработку |

## Не входит в утверждённый MVP

- Аккаунты, синхронизация нескольких устройств и полноценный облачный сервер с пользовательскими данными.
- Чат с нейросетью о книгах, массовый анализ всех заметок, автоматическое чтение полных текстов книг.
- Платные каталоги, покупка обложек, монетизация, подписки.
- Любая публикация и запуск платных ресурсов без отдельного решения владельца.

При новом решении записывать дату, краткую причину, затронутые требования и связанные ID задач. Не переписывать прошлые записи задним числом так, будто вопрос был утверждён ранее.
