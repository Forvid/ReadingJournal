# ReadingJournal — продукт и дорожная карта

**Дата актуализации:** 27.11.2026  
**Владелец:** Forvid  
**Формат работы:** обсуждение, требования и приёмка — вместе с ChatGPT; реализация и технические проверки — в отдельной сессии Codex.  
**Текущее состояние:** код v0.1; новый план согласован **на уровне архитектуры**, не реализован.

## 1. Задача продукта

Помочь человеку сохранять впечатление о книге за одну минуту и получать объяснимые персональные рекомендации. Сервис должен запоминать не только жанры, но и **темы, образы и вопросы**, которые затронули конкретного читателя.

Пользовательский сценарий:

1. Читатель добавляет книгу, выбирает статус и при желании отмечает оценку от 1 до 10.
2. По желанию записывает короткое впечатление — мысль, сцену, чувство или то, почему книга запомнилась. Обязательной анкеты нет.
3. Может самостоятельно отметить темы, а также **явно запросить** AI-анализ одной заметки. AI предлагает темы, человек подтверждает или редактирует их.
4. Приложение обновляет персональный топ непрочитанных книг и объясняет рекомендации на основе оценок и подтверждённых тем.

**Пример пользовательской потребности:** после «Соляриса» Станислава Лема человека зацепили чуждый разум, границы познания и попытка понять самого себя. Рекомендация должна учитывать именно этот смысл, а не только жанр научной фантастики. «История твоей жизни» Теда Чана — пример интересного кандидата, но не гарантированный результат алгоритма. Реальная оценка «Соляриса» от Forvid ещё не указана; не назначать её автоматически.

## 2. Цели и критерии успеха MVP

- Сценарий «открыть полку → записать впечатление → увидеть обновлённые рекомендации» работает с понятным объяснением.
- Для рекомендации не требуется регистрация или платный AI-запрос.
- Рекомендатель работает при отсутствии сети, используя уже сохранённые оценки и темы.
- Личные данные не публикуются и не передаются модели без отдельного подтверждения.
- При ошибке AI уже сохранённые книги и темы остаются доступны.
- Есть GitHub-репозиторий, инструкция запуска, тесты алгоритма и проверяемая публичная демоверсия с вымышленными данными после согласования релиза.

**Не измеряем успех количеством функций.** Для MVP важнее завершённый демонстрационный сценарий и корректные данные.

## 3. Что реально есть в v0.1

| Возможность | Состояние по коду | Что проверить |
| --- | --- | --- |
| Создание/редактирование книги, статусы, 1–10, заметка | Реализовано | Ручной сценарий и ошибки ввода |

| AI-анализ заметок | Отсутствует | Отдельный серверный вызов и согласие |

Старая программа `reading_journal_v2.html` и её пример JSON в этом архиве отсутствуют, поэтому реальная совместимость с прежним экспортом **не доказана**.

## 4. Границы утверждённой гибридной архитектуры

**AI делает:** выделяет из одной заметки 1–3 значимые темы из контролируемого словаря, предлагает короткое объяснение, на какой фразе заметки основана тема. Результат редактируем пользователем. Не выдумывает фактов сюжета.

**Алгоритм делает:** на основе пользовательских оценок и тем вычисляет профиль интересов, ранжирует непрочитанные книги из локального каталога, формирует объяснение из известных совпадений. Без внешнего AI. Подробнее — [RECOMMENDATION_ALGORITHM.md](RECOMMENDATION_ALGORITHM.md).

**Данные:** книжная полка и результаты подтверждённого анализа остаются локальными. На сервер отправляется только текст, который пользователь предварительно увидел и разрешил отправить. Облачная синхронизация и аккаунты не входят в MVP.

**Каталог:** для первой демонстрации ориентир 30–50 кандидатов с автором, названием, темами и источником метаданных. Число не жёсткое; качество и разнообразие важнее. Не загружать целые тексты книг или изображения без прав на использование.

## 5. Задания и статусы

ID из исходного плана сохранены ради непрерывности истории. **ID не равен порядку запуска**: последовательность зависит от зависимостей, указанных ниже.

| ID | Содержание | Статус | Приёмка Forvid |
| --- | --- | --- | --- |
| RJ-01 | Полка: создание и редактирование (пока без удаления), статусы, заметки, поиск, фильтры | В коде v0.1, приёмка не подтверждена | Создать/изменить запись, обновить страницу, найти книгу |
| RJ-02 | JSON-импорт/экспорт, PWA-оболочка | В коде v0.1, приёмка не подтверждена | Повторный импорт без дублей, сохранность данных, офлайн-тест |
| RJ-03 | **Уточнено:** AI выделяет и предлагает темы одной заметки, подтверждение и ошибки | Запланировано | Увидеть отправляемый текст, согласиться, получить/исправить темы, пережить ошибку API |
| RJ-04 | Демоверсия для GitHub-портфолио | Запланировано, публикация не разрешена | Открыть ссылку, пройти сценарий, увидеть честное описание функционала |
| RJ-05 | Словарь тем, каталог кандидатов и детерминированный алгоритм рекомендаций | **Следующее функциональное направление** | Оценка меняет топ; нет прочитанных/отклонённых; объяснения соответствуют данным |
| RJ-06 | Надёжность библиотеки, удаление, демоданные, тесты, обратная совместимость | Запланировано | Нет потери записей, данные демо не смешиваются, тесты проходят |

### Рекомендуемый порядок (после отдельных заданий Codex)

1. **RJ-05A:** согласовать словарь тем, структуру каталога и формулу без AI; добавить минимальные данные и тестовые примеры.
2. **RJ-05B:** вывести рекомендуемый топ и объяснения на основе оценок и тем.
3. **RJ-06:** закрепить тестами данные/импорт; обсудить удаление и отдельный деморежим; реализовать утверждённое.
4. **RJ-03:** после выбора провайдера и бюджета подключить AI для выделения тем через защищённую функцию.
5. **RJ-04:** после ручной приёмки согласовать публичный адрес, доступ и оформление GitHub.

Не делать несколько этапов одновременно и не считать будущие этапы разрешением на платные вызовы.

## 6. Открытые решения

См. [DECISIONS.md](DECISIONS.md). Особенно нужны утверждения по:

- Конкретному AI-провайдеру, допустимому месячному бюджету и условиям доступности.
- Изолированному деморежиму: пустая полка, демонстрационная библиотека или выбор при первом запуске.
- Составу стартового каталога и списку тем (включая разнообразие жанров).
- Поведению удалённых книг, импорту старого формата и сохранению данных при миграции.
- Публичному хостингу, домену и моменту публикации.

## 7. Условия для портфолио

- GitHub показывает небольшие осмысленные задачи и коммиты, документацию и тесты.
- README отделяет «уже работает» от «в планах».
- Роль Forvid описана честно: продуктовые решения, требования, проектирование алгоритма, контроль качества и приёмка; Codex помогает реализовывать код.
- Демоверсия использует вымышленные данные, не требует регистрации и даёт заметный результат за 2–3 минуты.
- Если AI ещё не доступен в конкретной сборке, интерфейс и README не утверждают обратное.

## 8. Безопасность данных

- `localStorage` принадлежит браузеру и адресу сайта: нет синхронизации, очистка браузера может удалить записи. Нужен JSON-бэкап.
- Импорт не должен перезаписывать существующие записи при сбоях или неизвестном формате.
- При будущих расширениях схема должна оставаться обратно совместимой с сохранёнными копиями v1/v2.
- AI не получает всю полку, историю оценок или личный профиль автоматически.
- Никакие сервисы не создаются и не оплачиваются до согласования Forvid.
