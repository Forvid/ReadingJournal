# Архитектура ReadingJournal

**Статус:** текущая v0.1 + целевая гибридная схема. Описания будущих модулей **не означают их реализацию**.

## 1. Текущее устройство v0.1

| Файл | Функция |
| --- | --- |
| `src/App.tsx` | Полка, фильтры/поиск, сохранение, импорт/экспорт, выбор редактора |
| `src/BookEditor.tsx` | Диалог создания/редактирования, статус, оценка, заметка |
| `src/books.ts` | Типы книги, примеры, проверка JSON, работа с `localStorage` |
| `src/styles.css` | Оформление и адаптивность |
| `src/main.tsx` | Запуск React и регистрация service worker |
| `scripts/build-service-worker.mjs`, `scripts/service-worker.js` | Генерация и работа офлайн-оболочки |
| `public/manifest.webmanifest` | Установка PWA |

`dist` в ZIP — готовая сборка исходной v0.1. При публикации исходников GitHub обычно исключает `dist` по `.gitignore`; это не ошибка.

## 2. Целевая структура компонентов (предложение Codex)

```text
UI: полка / запись / рекомендации / анализ заметки
  ↓
Домен: модель книги / профиль интересов / ранжирование / объяснения
  ↓                              ↘
Локальное хранение и миграции      Каталог книг и тематический словарь

Отдельный, явно подтверждаемый поток AI:
UI предпросмотра → защищённая серверная функция → AI-провайдер
               ← валидированные предложенные темы ←
```

Имена файлов и точная структура модулей определяются Codex в рамках отдельного задания. Главное — **чистое разделение доменной логики и интерфейса**.

## 3. Где хранятся данные

- **Полка и подтверждённые темы** — в текущем браузере пользователя, без аккаунта и облачной синхронизации.
- **Каталог кандидатов и словарь тем** — локальные статические данные приложения, версия которых связана с релизом.
- **AI-ключ** — только в защищённой серверной конфигурации, не в браузере и не в репозитории.
- **AI-запрос** — название/автор (по предусмотренному выбору) и **одна явно выбранная заметка**. Не загружать всю полку.

Результаты AI могут храниться локально после подтверждения; повторный запрос не нужен для каждого открытия рекомендаций. История прочтений и личные записи не отправляются автоматически.

## 4. Совместимость данных

Сейчас `src/books.ts` экспортирует JSON с `version: 1`; импорт допускает `version: 1` или `version: 2` только при ожидаемой структуре книг. Не предполагать, что произвольный старый файл версии 2 совместим: требуется образец из прежнего дневника и тест.

Если новые поля изменяют контракт:

1. Определить новую явную версию схемы и мигратор из поддерживаемых форматов.
2. Прежде чем менять хранилище, убедиться, что исходный JSON можно экспортировать.
3. Ошибочная миграция **не должна перезаписывать** исходные данные; показывать понятную ошибку.
4. Обеспечить экспорт новой схемы, обратную загрузку и проверку повторного импорта.
5. Не записывать сырые ответы AI как доверенные данные без проверки формата и согласия пользователя.

## 5. Серверная часть AI

Для гибридного MVP достаточно небольшой **serverless-функции**, а не постоянно работающего сервера. Сначала утверждаются провайдер, место размещения и лимиты расходов. Возможный кандидат — Yandex AI Studio (Alice AI LLM Flash), но окончательный выбор **открыт**.

Серверная функция должна:

- принимать только разрешённый тип запроса и ограниченный объём текста;
- не раскрывать секретный ключ клиенту;
- применять ограничение частоты вызовов и месячный бюджет/квоту приложения;
- проверять ответ модели на ожидаемую структуру;
- возвращать контролируемые ошибки без личных данных/секретов в ответе;
- не считать AI доступным, если серверный маршрут не развернут.

**Важно для публичного демо:** отсутствие регистрации не отменяет защиту от автоматических массовых запросов. До проверки ограничений платный AI нельзя открывать всем посетителям.

## 6. Офлайн и публикация

- Полка, оценки, заметки, профиль интересов, рекомендательный алгоритм и каталог — локальные функции.
- AI-анализ требует сеть и согласие пользователя. При отсутствии связи интерфейс не должен обещать онлайн-анализ.
- PWA-кеш обеспечивает загрузку оболочки при выполненных условиях установки, но не синхронизирует данные между устройствами.
- Публикация GitHub и статического сайта — отдельный шаг только после проверки личных данных, лицензий, конфигурации и разрешения Forvid.

## 7. Оценка бюджета для планирования (27.11.2026)

Кандидат Alice AI LLM Flash, тариф для России с НДС: **0,10 ₽ / 1 000 входящих токенов** и **0,20 ₽ / 1 000 выходных**. Пример 800 входящих + 250 выходных = **0,13 ₽ за анализ**; 1 000 таких анализов ≈ **130 ₽** за модель. Это иллюстрация, не гарантия расхода и не тариф всей инфраструктуры.

Источники:

- [Yandex AI Studio — тарифы моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing)
- [Yandex Cloud Functions — тарифы и бесплатные квоты](https://yandex.cloud/ru/docs/functions/pricing)
- [Yandex Object Storage — тарифы и бесплатные квоты](https://yandex.cloud/ru/docs/storage/pricing)

У Cloud Functions первые 1 млн вызовов и 10 ГБ·часов в месяц не тарифицируются; у Object Storage — первый 1 ГБ стандартного хранения и ограниченное количество операций. **Трафик, домен, другие платные ресурсы и превышение квот считаются отдельно.** Перед реальным подключением проверить актуальность тарифов и настроить защиту от превышения расходов.
